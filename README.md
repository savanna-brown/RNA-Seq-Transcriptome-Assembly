



## Project directory setup

Before running any analyses, it can be helpful to set up a directory structure for the project. This keeps inputs, outputs, and logs for different operations organized.

**Important note on running scripts in general:**
- Every script submitted to the scheduler must include a valid **bash header** including `#SBATCH` directives.
- **CPU cores and memory requirements will need to be adjusted based on the tools and datasets being used**; always adjust `-c` and `--mem` based on the job being run.
- The directory specified by `#SBATCH -o` (where stdout/error logs are written) **must exist before the job is launched in SLURM**, or the job will fail immediately.
- Pre-creating log directories for each major computational step helps avoid silent failures and keeps outputs organized.

The script below initializes a standard directory structure for a de novo transcriptome assembly / RNA-seq project, from raw read QC through expression quantification.

## 1) **Initial Quality Control & Adapter Trimming of Raw Reads**

Raw RNA-seq reads often include sequencing adapters, low-quality bases (especially toward read ends), and platform-specific artifacts that should be removed before downstream analyses. If these are not removed, they can reduce alignment accuracy, inflate noise in expression estimates, complicate de novo assembly, and increase runtime for downstream tools.

Quality control and trimming are therefore an essential first step for transcriptome assembly and RNA-seq workflows.


<br>

### **`fastp`**
`fastp` is an all-in-one read processing tool that performs filtering, adapter trimming, and quality reporting in a single step. 



#### **Key operations performed by `fastp`**
- **Adapter trimming:** Automatically detects and removes TruSeq adapter sequences (standard in Illumina sequencing). Custom adapter sequences can also be provided.
- **Quality filtering:** Trims low-quality bases from read ends using a sliding-window–style approach based on Phred quality score thresholds.
- **Poly-G tail trimming:** Removes artificial poly-G tails generated by two-color Illumina chemistry (NovaSeq, NextSeq, iSeq).
- **Base correction:** Corrects mismatched bases in overlapping paired-end reads.

<br>

**INPUTS** — Raw paired-end FASTQ files (`*.fastq.gz`)  
&nbsp;&nbsp;↳ Location: external sequencing directory (e.g. `/path/to/raw_reads/`)

**OUTPUTS** — Trimmed FASTQ files; `fastp` HTML/JSON QC reports  
&nbsp;&nbsp;↳ Locations: `1_READ_QC/trimmed_sequences/`, `1_READ_QC/fastp/`, `1_READ_QC/logs/`

<br>



### **Interpreting `fastp` Reports**

After preprocessing, `fastp` generates an interactive HTML report for each library. These reports summarize read quality before and after trimming and should be reviewed to ensure reads are suitable for downstream analyses.

What constitutes “good” or “good enough” read quality is context dependent (organism, tissue type, sequencing depth), but the metrics below provide a broadly applicable framework for assessing overall read quality.

<br>

### **Key metrics to evaluate in `fastp` HTML reports**

| Assessment | **Per-base quality** | **GC content** | **Duplication rate** | **Read length after trimming** | **Adapter content** |
|-----------|----------------------|----------------|----------------------|-------------------------------|---------------------|
| **Green flags (expected)** | Most bases ≥ Q30 | Single, smooth peak | ~20–60% duplication is typical in RNA-seq | Majority of reads near expected length | Near zero after trimming |
| **Potential red flags** | Early quality drop in read 1 or read 2 | Strong bimodality or jagged peaks | Very high duplication (>80%) | Large fraction of very short reads | Persistent adapter signal |
| **Important caveats** | Mild 3′ quality decay is common | Some tissues or mixed RNA sources can cause deviation | Duplication varies widely in RNA-seq | Can result from aggressive trimming | May indicate ultra-short inserts |

### *SCRIPT*  

<details>
<summary><strong>RUN fastp</strong></summary>
  
<br>

**Note:**  
- This script assumes paired-end reads are named with `_R1_` / `_R2_`. Adjust filename patterns if your data use a different naming convention.

- This script uses GNU Parallel to process multiple samples simultaneously. Four samples are run in parallel (`-j 4`), with two threads allocated to each `fastp` job (`--thread 2`), fully utilizing an 8-core allocation.*

```bash
#!/bin/bash
#SBATCH --job-name=fastp_QC
#SBATCH -N 1
#SBATCH -n 1
#SBATCH -c 8
#SBATCH --mem=100G
#SBATCH --qos=general
#SBATCH -o /labs/Jockusch/Savanna/LEAFHOPPER/01_ReadQC/logs/%x_%A.out

echo "Start: $(date)"

module load fastp/0.23.2
module load parallel/20180122

INDIR="/seqdata/CGI/Fastq_Files/EJockusch_RNAseq_13Jan2026"

OUTBASE="/labs/Jockusch/Savanna/LEAFHOPPER/01_ReadQC"
REPORTDIR="${OUTBASE}/fastp"
TRIMDIR="${OUTBASE}/trimmed_sequences"

mkdir -p "$REPORTDIR" "$TRIMDIR"

ls "$INDIR"/*_R1_*.fastq.gz | parallel -j 4 \
  fastp \
    --in1 {} \
    --in2 {//}/{= s/_R1_/_R2_/ =} \
    --out1 "$TRIMDIR"/{= s/_R1_.*// =}_trim_R1.fastq.gz \
    --out2 "$TRIMDIR"/{= s/_R1_.*// =}_trim_R2.fastq.gz \
    --json "$REPORTDIR"/{= s/_R1_.*// =}_fastp.json \
    --html "$REPORTDIR"/{= s/_R1_.*// =}_fastp.html \
    --thread 2

echo "Finished: $(date)"
```

### **`MultiQC`**

Because most projects involve many libraries, it is often helpful to summarize QC results across all samples. `MultiQC` aggregates output from individual `fastp` reports into a single interactive report, making it easier to identify global trends and outliers across libraries.

#### **Key operations performed by `MultiQC`**
- **Multi-library QC aggregation:** Parses output files from `fastp` across all samples and creates interactive plots and tables for rapid assessment of sequencing quality across an entire dataset.


<br>

**INPUTS** — `fastp` report files (`*.json` and/or `*.html`)  
&nbsp;&nbsp;↳ Location: `1_READ_QC/fastp/`

**OUTPUTS** — MultiQC HTML report; MultiQC data directory  
&nbsp;&nbsp;↳ Location: `1_READ_QC/multi_QC/`

<br>

### *SCRIPT*

<details>
<summary><strong>RUN MultiQC</strong></summary>

<br>

**Notes:**  
- This script summarizes all `fastp` reports found in the specified directory into a single MultiQC report.  
- If multiple QC tools are present in the directory, MultiQC will automatically detect and include them unless filtered.

```bash
#!/bin/bash
#SBATCH --job-name=multiQC
#SBATCH -N 1
#SBATCH -n 1
#SBATCH -c 2
#SBATCH --mem=10G
#SBATCH --qos=general
#SBATCH -o /home/FCAM/sabrown/TEST_SET/1_READ_QC/logs/%x_%A.out

echo $(hostname)
date

###############################################
#      MultiQC summary of fastp QC results    #
###############################################

module load MultiQC/1.15

BASE_DIR=/home/FCAM/sabrown/TEST_SET
FASTP_DIR=${BASE_DIR}/1_READ_QC/fastp
OUTPUT_DIR=${BASE_DIR}/1_READ_QC/multi_QC

# Ensure output directory exists
mkdir -p "$OUTPUT_DIR"

# Run MultiQC
multiqc "$FASTP_DIR" \
  --outdir "$OUTPUT_DIR" \
  --title "fastp QC summary" \
  --verbose

echo "MultiQC report generated in: $OUTPUT_DIR"
date
```
